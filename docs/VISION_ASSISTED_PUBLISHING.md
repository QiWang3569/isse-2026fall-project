# 识图辅助发布：调研与实现方案

调研日期：2026-10-23。本文是下一阶段方案，尚未实现识图接口、调用付费模型或发送用户照片。

## 建议范围

首版在商品发布表单上传区增加“看图填写”。用户从已上传的最多 9 张照片中选 1–3 张，模型生成标题、分类、描述和标签建议；用户确认后填入表单，最后自行发布。建议使用同一件商品的整体照、标签/书名照、细节照。

价格、交易校区、购买时间、功能是否正常和几成新仍由用户填写。品牌、型号只在照片文字清楚时提供候选，并标明来源图片；不能从外观确定的信息保持空值。多件不同商品、模糊图片、无法识别时，提示补拍或补充文字。

优先验证现有七牛接口能否调用合适的视觉模型；若当前账号或转发接口不支持，再接阿里云百炼。当前规模先使用托管 API；识图填表本身不需要训练模型或新增向量数据库。

## 现有代码可复用的部分

| 位置 | 现状 | 接入方式 |
| --- | --- | --- |
| `frontend/src/forms.tsx` 的 `ItemForm` | 图片上传、九张限制、文本智能填写和草稿 | 在上传成功后增加识图入口与建议确认区 |
| `backend/app/main.py` 的 `save_image` | 图片验证、JPEG 保存、按用途区分路径、上传者登记 | 服务端从已授权的商品图片读取识图输入 |
| `backend/app/models.py` 的 `Upload` | 记录 `path` 与 `user_id` | 检查每张图属于当前账号，限制为商品上传路径 |
| `backend/app/services.py`、`schemas.py` | 文本解析和字段规则 | 复用分类、长度等业务校验，新建视觉草稿结构 |
| `docs/BUYER_AGENT.md` | 记录七牛兼容接口与 `qwen/qwen3.7-flash` 的文本调用 | 可作为候选配置；历史文本调用成功不等于视觉调用已验证 |

现有 `ParsedItem` 默认校区为“燕园校本部”、成色为“95新”；`smartFill()` 会直接覆盖返回字段。识图应使用独立 `VisionDraft`，没有证据的字段为 `null`，并在前端确认后应用。原表单已有默认值也不能显示成“AI 已识别”，价格、校区与成色需要用户确认。

本工作树没有配置模型凭证，本次没有查询账号可用模型或测量识图效果。

## 接入方案比较

| 方案 | 官方能力与项目适配 | 决策 |
| --- | --- | --- |
| 现有七牛兼容接口 + 账号可用的视觉模型 | 七牛文档给出图文混合的 `image_url` 输入方式；可沿用兼容 Chat Completions 的调用结构。当前模型 ID、Base64 支持和结构化输出需实际探测 | 第一候选，接入改动较少 |
| 百炼直连 Qwen3.7-Flash | 官方视觉文档列有该模型，支持图像输入；结构化输出文档列明支持 JSON Schema。需要独立密钥与工作空间配置 | 七牛不可用时的备选，也可用于样本对照 |
| 自托管 Qwen3-VL | 官方仓库提供 vLLM/SGLang 服务方式 | 需要 GPU 资源及推理服务维护，当前首版不采用 |

依据：[七牛多模态接口示例](https://developer.qiniu.com/aitokenapi/12993/model-features-multimodality)、[百炼视觉理解](https://help.aliyun.com/zh/model-studio/vision)、[百炼结构化输出](https://help.aliyun.com/zh/model-studio/qwen-structured-output)、[Qwen3-VL 官方部署说明](https://github.com/QwenLM/Qwen3-VL#deployment)。表中优先级是结合本项目已有接口作出的工程判断。

第一步用非用户数据完成小样验证：单图、三图、中文标签、不确定物品各一例，记录返回模型、耗时和用量。模型 ID 从服务商实际可用列表选取；确认支持图文输入后，再测 `json_schema`。若只支持 `json_object`，仍需服务端解析和校验字段；Schema 约束也不能替代事实核查。

## 页面流程

1. 图片上传完成后启用“看图填写”；上传中、无图、识别进行中不允许重复提交。首次使用在按钮附近说明“所选图片将发送至识图服务生成建议”。
2. 展示所选 1–3 张图，可改选；允许补充一句说明，例如“这是书和配套习题册一起出”。点击后显示进度状态，保留手动输入能力。
3. 展示可勾选的标题、分类、描述和标签建议，以及“需要你补充”的问题。不用未经校准的百分比显示所谓识别置信度。
4. “应用所选建议”只修改选中字段。请求期间用户编辑过的字段需要再次确认，不被旧结果覆盖；改图后旧结果失效。
5. 识图失败保留图片和表单，提供重试。发布仍走原来的商品校验与提交接口。

## 后端接口与边界

新增 `POST /api/v1/items/vision-draft`，要求登录。请求示例：

```json
{
  "images": ["/uploads/已有商品图片.jpg"],
  "note": "配套习题册一起出售"
}
```

接口处理顺序：

1. 校验 1–3 张不同图片及补充文字长度；验证 `Upload.user_id`、商品图片路径、规范化后的实际文件位置及文件存在性。拒绝任意远程 URL、路径穿越、他人图片和聊天/反馈附件。
2. 从已保存的 JPEG 生成识图副本，建议长边 1280–1600 像素；单图目标不超过 1 MB，总请求体上限 6 MB，超出则压缩或明确报错。这些是本项目建议限额，最终应取服务商限制与项目限制的较小值。书名/型号小字不清楚时提示补拍近照。
3. 通过支持的 Base64 图像输入传给服务商，不把服务器本地路径当公网 URL，也不为识图临时开放私有图片。若选定网关不支持 Base64，再评估短时签名 URL 的实现。
4. 返回受业务规则约束的 `VisionDraft`：`title`、`category`、`description`、`tags`、带 `photo_indices` 的可见属性、`uncertainties`。字段可空，分类必须来自项目枚举；价格、校区与成色不由模型自动填写。
5. 不调用商品创建接口。仅记录模型、耗时、Token、错误类型和请求标识；不把原始图片或 Base64 写进应用日志。

新增 `backend/app/vision.py` 集中封装调用，配置独立的 `VISION_ENABLED`、`VISION_BASE_URL`、`VISION_API_KEY`、`VISION_MODEL` 和超时参数。可以显式复用现有服务商凭证，但不因文本 AI 开启就自动启用视觉功能。

建议总请求时间预算 30 秒，对 429/5xx 最多重试一次并遵守剩余预算；验证错误不重试。每用户先限 20 次/小时并可配置，限制并发和输出长度。采用用户范围内的“图片内容摘要 + 补充文字 + 模型 + 提示词版本”短时缓存及进行中请求去重，避免重复点击产生重复费用。外部 HTTP 调用期间不持有数据库写锁。

提示词将照片中的文字视为待识别内容。模型输出仍作为不可信数据进行字段校验，并使用 React 文本渲染；图片里的指令不能触发工具、修改系统设置或绕过商品发布校验。

## 费用估算

截至调研时，百炼北京地域 Qwen3.7-Flash 在单次输入不超过 32K Token 的档位，输入为 0.2 元/百万 Token，输出为 0.8 元/百万 Token。[官方价格表](https://help.aliyun.com/zh/model-studio/model-pricing)

假设一次识别共消耗 2,000 输入 Token（包含图片）和 400 输出 Token，模型费为 `(2000 × 0.2 + 400 × 0.8) / 1000000 = 0.00072` 元，1,000 次约 0.72 元。这里的 Token 数是计算示例；实际费用要用样本返回的用量统计，并计入重试。该价格不代表七牛的实际报价，也不包含存储与网络费用。

首轮选型主要比较字段准确性、响应时间和失败率；费用在真实样本上测量后再确定预算与限额。

## 实施顺序与验收

| 阶段 | 交付内容 | 预计开发时间 |
| --- | --- | --- |
| 能力探测 | 确认账号、模型、图片格式、JSON 模式和真实用量 | 0.5 天 |
| 后端 | 权限校验、图像副本、VisionDraft、限流、超时与替身测试 | 1 天 |
| 前端 | 选图、建议确认、字段冲突、失败恢复、草稿联动 | 1 天 |
| 样本验收 | 模型对照、移动端流程、错误与越权验证 | 0.5–1 天 |

预计 3–3.5 个开发日，账号或模型接口不可用时需另计接入等待时间。完成后以功能开关关闭的状态交付，是否上线另行安排。

准备 30–50 组经过许可的校园二手商品照片，覆盖书籍、电子产品、衣物、运动用品；包含模糊、反光、标签缺失、两件不同物品和印有指令文字的难例。记录分类准确率、标题采纳率、无依据的品牌/功能断言、人工修改量、P50/P95 延迟及每次 Token 成本。

建议验收目标：清晰且品类明确的样本分类正确率至少 90%；不得凭照片确定功能正常、使用年限或成色等级；失败时图片与手动输入完整保留；旧请求不得覆盖后续编辑；所有越权图片请求在调用模型前被拒绝。目标响应 P95 不超过 15 秒，需以实测判断是否达到。这些均是拟定目标，尚无本项目识图实测结果。

暂不纳入首版：自动估价、自动发布、以图搜同款、识图向量检索和模型微调。若书籍识别的小字成为主要错误来源，再增加 ISBN/OCR 定向辅助，依据样本结果决定。
