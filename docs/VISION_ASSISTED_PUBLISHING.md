# 识图发布

实现日期：2026-10-23。代码已接入商品发布、编辑与草稿完善表单；默认关闭，尚未部署。按钮名称为“识图发布”。

## 用户流程

1. 仍可上传最多 9 张商品照片，识图时选其中 1–3 张，默认选择第一张。可补充一句说明，例如“只卖鼠标，不包含背景键盘”。
2. 用户主动点击“识图发布”，才会将所选照片和说明发送至识图服务。上传本身不触发模型调用。
3. 展示可编辑的标题、分类、描述和标签建议，注明“AI 建议，请核对后使用”。空字段默认勾选；已有内容默认不勾选，并显示当前值及替换提示。
4. 点击“应用所选建议”填入原表单，再按原有流程发布。价格、校区和成色保持原表单值，需要用户确认。

新商品的分类从“请选择商品分类”开始，避免把默认的“课程资料与书籍”误当成已填写内容；识图分类可随其他空字段一并应用。已有商品、草稿或回应求购时的分类仍然保留。

换图、增删照片、改选照片或修改补充说明会废弃当前建议并取消浏览器请求。请求期间手动填写的字段不会默认勾选；建议出现后再次修改原表单，对应选项会取消勾选。所有修改都只影响本地表单，识图接口不会创建商品或保存草稿。

照片不清楚、多件不同商品、调用失败时可以重新识别或继续手填，已有照片和内容保留。浏览器取消请求后，已开始的服务端调用可能继续至完成或超时；同组输入重试会合并进行中的请求或复用短时缓存。

## 接口与实现

`POST /api/v1/items/vision-draft`，要求登录，沿用站点的来源校验。请求：

```json
{
  "images": ["/uploads/00000000-0000-0000-0000-000000000000.jpg"],
  "note": "只卖鼠标"
}
```

响应示例：

```json
{
  "status": "ready",
  "title": "黑色鼠标",
  "category": "数码与影音",
  "description": "黑色鼠标，顶部可见滚轮。",
  "tags": ["鼠标", "黑色"],
  "uncertainties": ["请确认功能及包含的配件。"]
}
```

`status` 也可为 `unclear` 或 `multiple_items`，此时服务端强制清空建议字段，保留原因。返回结构不含价格、校区、成色、功能或使用年限字段。标题、描述、标签长度及分类枚举由 Pydantic 校验，额外字段与不完整 JSON 均拒绝，不直接透传供应商报错。

- `backend/app/vision.py`：验证 `Upload.user_id`，仅接受商品上传路径。拒绝远程 URL、重复照片、越权照片、聊天/反馈附件和路径穿越；每次请求（包括缓存命中）重新检查权限与文件。
- 图片从本地读取，校验最多 6 MB、2000 万像素，转换为长边不超过 1280 的 JPEG 后，以 Base64 发送。图像处理和网络请求前释放数据库连接，不持有写锁。
- 模型使用 Chat Completions 的 `json_object` 输出。整个调用默认限时 30 秒，429/5xx 最多重试一次；HTTP 重定向关闭。
- 每个用户最多一个不同输入的进行中请求，全进程最多四个；同用户同输入合并。每小时默认 20 次新识别请求（失败也计数，内部最多两次供应商调用）。缓存 5 分钟，最多 128 条，键包括用户、图片内容摘要、说明、模型和提示词版本。
- 限流、缓存与进行中请求保存在单个应用进程内，重启会清空。多 worker/多实例部署前需改为 Redis 或数据库共享限流。
- 日志只记录结果类型、图片数量和耗时，不记录原图、Base64、补充说明、密钥或完整模型响应。
- `frontend/src/VisionPublisher.tsx`：选图、请求取消、建议编辑和逐字段替换保护；复用 `PublishForm` 的保存与发布操作。

## 配置

独立于文本解析的 `AI_MODE` / `DEEPSEEK_*`。只有配置开启时，页面才显示识图助手。示例见根目录 `.env.example`：

```dotenv
VISION_ENABLED=false
VISION_API_KEY=
VISION_BASE_URL=https://api.qnaigc.com/v1
VISION_MODEL=qwen/qwen3.7-flash
VISION_THINKING=disabled
VISION_TIMEOUT_SECONDS=30
VISION_HOURLY_LIMIT=20
```

启用前填入该服务商的有效密钥并设 `VISION_ENABLED=true`；配置随后端启动生效。可显式配置与文本服务相同的七牛密钥，但代码不会自动复用 `DEEPSEEK_API_KEY`，也不会改动文本模型。其他兼容服务不支持 `thinking` 时设 `VISION_THINKING=`。Base URL 必须使用 HTTPS；超时范围 1–60 秒，每小时限额范围 1–100。

本次没有修改生产环境配置、重启应用或部署代码。默认关闭仍可运行全部原有功能。

## 实测与限制

2026-10-23 通过现有七牛账号确认 `qwen/qwen3.7-flash` 可用，并完成了此前 11 次探测与本次实际服务模块的 6 次调用。只使用公开鼠标/网球拍照片、自制中文书籍封面卡片和空白图，不使用站内用户照片。

此前探测验证了 Base64、多图、JSON 输出与中文文字识别，11 次调用均返回 HTTP 200。平均服务端耗时 4.72 秒，范围 2.67–7.86 秒；这是少量样本结果，不能代表线上准确率或 P95。

本次实际服务模块两轮各测试鼠标、虚构书籍封面和空白图，六次均通过响应结构校验，耗时 1.96–3.07 秒。鼠标分类正确，空白图返回 `unclear`；模型把印有“测试虚构封面”的卡片也判为 `unclear`。收紧提示词后，鼠标描述仍出现无法由照片证明的“无线”，因此必须保留人工核对，JSON 合法不等于内容可靠。尚未完成 30–50 组真实校园商品的准确率与采纳率评估。

上线前建议用经许可的书籍、电子产品、衣物、运动用品照片评估分类、无依据属性、人工修改量与延迟，并覆盖模糊、反光、背景干扰和多件商品。当前不包含自动估价、自动发布、同款搜索、向量检索或模型微调。

供应商参考：[七牛模型列表](https://www.qiniu.com/ai/models)、[Chat Completions 文档](https://developer.qiniu.com/aitokenapi/13390/chat-completions)。替代方案仍可使用支持图片输入的兼容 API；首版采用已实测的七牛通道。
