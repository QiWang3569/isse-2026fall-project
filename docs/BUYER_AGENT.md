# 买家代蹲助手使用说明

## 可以做什么

输入“万柳 300 元以内无线鼠标，不要游戏鼠标，最好静音”，助手分别提取：

- 必须满足：鼠标、无线；价格不超过 300 元；万柳校区。
- 不接受：游戏鼠标。
- 可选偏好：静音。未满足偏好也可能推荐。

用户确认或修改条件后，系统保存代蹲任务。远程模式在后台检查现有商品，新商品发布、重新上架或管理员恢复商品时会再次检查。通知包含商品描述中的原文依据；缺乏关键证据时显示“可能合适，部分条件待确认”，并列出需要向卖家询问的问题。这些问题会加入可编辑咨询草稿，也可带入站内聊天输入框，但仍须由用户确认发送。

## 首次启用：只需要聊天模型密钥

将项目根目录的 `.env.example` 复制为 `.env`，在自己的编辑器中填写以下配置，随后重启后端：

```dotenv
AI_MODE=remote
EMBEDDING_MODE=local
DEEPSEEK_API_KEY=在本机填写你的密钥
DEEPSEEK_BASE_URL=https://api.deepseek.com
DEEPSEEK_MODEL=deepseek-chat
MODEL_TIMEOUT_SECONDS=20
MATCH_MAX_ATTEMPTS=3
```

`DEEPSEEK_BASE_URL` 与 `DEEPSEEK_MODEL` 应按供应商的当前文档填写，模型需要支持 Chat Completions 和 JSON 输出。变量名保留旧项目命名，但也可配置其他兼容供应商的接口和模型。Base URL 是追加 `/chat/completions` 前的 API 根地址，例如供应商使用 `/v1/chat/completions` 时应填 `https://供应商域名/v1`。

不要把密钥写入 `frontend` 或使用 `VITE_` 前缀。浏览器只请求项目后端，后端负责调用供应商。`.env` 已被 Git 忽略。远程模式会把用户需求和经过硬过滤的候选商品标题、描述及标签发送至配置的模型接口，不会额外附带账号身份、用户档案中的联系方式、会话 Cookie 或上传图片；需求和商品文本中自行填写的信息仍会随文本发送。

单聊天密钥模式使用本地关键词覆盖率排序候选商品，再交给模型语义精筛；`MATCH_THRESHOLD` 不作为此模式的语义门槛。原演示商品不需要向量回填。单次核对最多 10 件候选商品，因此这不是全库语义召回；商品量大后建议接入向量接口。

## 可选：接入向量接口

在上述聊天配置之外，设置：

```dotenv
EMBEDDING_MODE=remote
EMBEDDING_API_KEY=在本机填写向量接口密钥
EMBEDDING_BASE_URL=https://api.openai.com/v1
EMBEDDING_MODEL=text-embedding-3-small
MATCH_THRESHOLD=0.82
```

向量接口必须支持 `/embeddings` 并返回 1536 维向量。发布商品和确认代蹲任务时会生成向量；失败时不保存半完成商品或任务。

向量模式先进行硬过滤，再依据向量相似度和阈值召回候选，然后进行模型精筛。旧 `local-keyword` 商品与远程向量不会混用，演示种子没有远程向量；此版本未提供向量回填命令，请在新的开发数据库中上传新商品测试，或自行完成数据回填。向量相似度不是交易成功概率。

兼容旧配置：如果没有设置 `EMBEDDING_MODE`，`AI_MODE=remote` 且存在向量密钥时自动启用远程向量；没有向量密钥则采用本地候选召回。明确设置 `EMBEDDING_MODE=local` 可避免意外调用向量服务。

## 体验流程

1. 按项目 README 安装、构建并启动。默认本地模式即可查看全部界面，远程模式需要上述配置。
2. 使用买家演示账号，在首页输入复杂需求，点击“帮我代蹲”。
3. 点击“理解我的需求”，检查预算、校区、必须特征、排除项与偏好。助手有疑问时可修改原句重新理解，也可直接修改结构化条件。
4. 点击“确认条件，开始代蹲”。远程核对在后台进行，网页每 10 秒读取任务和通知状态。
5. 任务卡片“累计发现”只展示当前愿望的通知，零匹配时显示空结果；顶部铃铛展示全部愿望的通知。在通知中展开核对依据，查看待确认问题，打开商品生成咨询草稿。
6. 切换卖家发布新商品，再切回买家观察新增通知。

## 任务重试与旧数据库

模型超时、限流、无效 JSON、未知商品 ID、缺失候选或引用不存在的商品文字时，系统不写入未经校验的通知。匹配任务已经保存，会按 2 秒、4 秒等退避间隔自动重试，默认最多尝试 3 次。达到上限后显示失败状态，买家可点击“重新核对”。每次手动重试会重置尝试次数，可能产生新的模型费用。

需求解析失败与匹配失败分别处理：解析失败时表单保留原输入供重试；匹配失败时已确认的代蹲任务保留。服务重启后恢复未完成的匹配任务，已通知的商品不重复通知，也不重复调用精筛模型。

启动时自动对旧表新增排除项、偏好、通知证据等字段，并创建 `match_jobs` 表。原商品、用户、任务、收藏和通知均保留。旧通知显示原理由，新增证据字段为空；不会追溯调用模型重新审核原通知。

## 实现与限制

- 这是固定步骤的买家智能体工作流。模型负责结构化需求理解与候选判断，程序负责查询、硬条件、任务状态、权限、去重和写入；没有任意 SQL、自动交易或自动消息发送能力。
- 远程请求在数据库会话和写锁之外执行，写通知前再次检查商品、任务、有效期和硬条件，防止核对期间售出或暂停导致误通知。
- 队列持久化在同一数据库，当前每个服务进程一个后台 worker。仅使用一个服务进程启动，不加 `--workers`；多进程或生产部署需共享队列及迁移协调。
- 单聊天密钥模式对经过硬过滤的候选做关键词排序；最多 10 件进入模型，可能漏掉关键词表达差异较大的商品。SQLite 向量模式仍为 Python 计算相似度，未做性能优化。
- 本地规则只支持简单句式，不能可靠理解所有中文否定和条件组合；商品真实性、卖家信誉、保修和未披露性能也不能仅凭文本确认。
- 已在本机通过七牛云千问 Flash 的真实需求解析和品类精筛测试；其他供应商、模型、完整语义质量、PostgreSQL 和并发性能尚未进行完整测试。源码包不包含任何真实密钥。

模型 JSON 输出接口参考：[DeepSeek JSON Output 官方说明](https://api-docs.deepseek.com/guides/json_mode/)。


## 七牛云配置与网球拍验证（2026-09-27）

本机后端已配置七牛云接口并重启。源码包不包含本机 `.env`，其他成员需要在自己的本机配置密钥：

```dotenv
AI_MODE=remote
EMBEDDING_MODE=local
DEEPSEEK_BASE_URL=https://api.qnaigc.com/v1
DEEPSEEK_MODEL=qwen/qwen3.7-flash
MODEL_THINKING=disabled
MODEL_TIMEOUT_SECONDS=45
DEEPSEEK_API_KEY=在本机填写密钥
```

模型 ID 由七牛云 `/v1/models` 实际返回的可用列表选取，并已通过真实 Chat Completions JSON 请求验证。非思考模式用于需求提取和有据可查的短文本核对。

真实测试中，“燕园本部的二手网球拍，价格不限，最好是进阶款，可以用的时间长一点”被解析为：必须物品“网球拍”、校区“燕园校本部”、无价格上限、偏好“进阶款”和“耐用”。羽毛球拍判定为 `NO_MATCH`，明确描述为二手进阶款网球拍的测试商品判为 `MATCH`。这些是有限样例验证，不代表所有品类都不会误匹配。

同时修复本地解析丢失具体球拍品类的问题：网球拍和羽毛球拍分别保留具体关键词，不再统一简化为“球拍”。本机原来的网球拍许愿已恢复该具体关键词；错误的羽毛球拍通知保留在数据库中用于追溯，但标记不符合并从通知与命中数中排除。

七牛云官方接口文档：[实时推理接入](https://developer.qiniu.com/aitokenapi/13379/real-time-ai-interface-api)、[聊天补全参数](https://developer.qiniu.com/aitokenapi/13390/chat-completions)。
