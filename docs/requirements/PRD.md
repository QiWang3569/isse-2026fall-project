# 「燕渡」校园二手交易智能体——完整系统需求规格说明书 (PRD)

---

## 1. 项目概览

### 1.1 基本信息
* **项目名称**：燕渡 (YanDu)[cite: 2]
* **命名由来**：取自「旧物渡新主，学海渡轻舟」。毕业季学长学姐的教材、器材流转到学弟学妹手中，不仅让闲置物品重新利用产生价值，更是燕园知识、生活经验与校园记忆的温情传承[cite: 2]。

### 1.2 产品定位与核心目标
* **产品定位**：基于意图驱动的校园闲置物品流转与自主撮合智能体系统[cite: 2]。
* **总体目标**：整合校园闲置物品交易信息，实现智能查找、匹配与主动推荐，消除信息时滞，帮助校内同学以更低的沟通成本、更有人情味的方式完成二手物品流转[cite: 2]。
* **核心价值主张**：
  1. **一次委托，系统持续关注**：买家无需大海捞针，向系统提交购买需求（如「留意 300 元内二手显示器」），智能体 24 小时全天候在后台持续关注新上架商品[cite: 2]。
  2. **秒级匹配，主动推送**：一旦有卖家发布符合条件的商品，系统第一时间私信通知买家，避免错过被新消息淹没的商品信息[cite: 2]。
  3. **告别手动狂刷**：把被动反复刷新转变为「委托智能体持续关注」，彻底免去频繁刷新页面的焦虑与时间浪费[cite: 2]。

## 2. 系统总体架构与角色矩阵

```text
校园统一身份认证门户 [cite: 2]
            │
            ├── 买家端角色 (Buyer) ──┐
            ├── 卖家端角色 (Seller) ─┤
            └── 管理端角色 (Admin) ──┤
                                     ▼
                             燕渡智能体核心引擎
                              (YanDu Agent Core)
```

| 角色 | 权限与定位 | 核心职责 |
| :--- | :--- | :--- |
| **买家 (Buyer)** | 经校园认证学生/教职工[cite: 2] | 意图委托代蹲、分类导航、混合检索、发起求购、接收推送、安全线下当面交易[cite: 2] |
| **卖家 (Seller)** | 经校园认证学生/教职工[cite: 2] | 多模态商品草稿生成、商品状态管理、托管代回复、响应求购推送[cite: 2] |
| **管理端 (Admin)** | 系统运维与学生管理团队 | 多模态自动合规审核、违规内容拦截、争议智能摘要、人机协同仲裁[cite: 2] |
| **撮合智能体** | 系统常驻后台智能体 | 漏斗式过滤、语义匹配验证、动态失效检测、求购定向征询 |

## 3. 功能详细规格说明

### 3.1 基础设施：校园统一身份认证
* **功能描述**：买家与卖家首次登录系统须通过校园门户身份认证[cite: 2]。
* **业务规则**：
  * 未经认证用户仅限只读预览部分热门商品，不可进行发帖、委托、聊天与求购[cite: 2]。
  * 认证成功后自动绑定校区（燕园校本部、万柳学区、医学部等）与院系基础信息，为后续时空撮合提供特征依据。

---

### 3.2 商品类别与细分市场划分
为了平衡「智能代蹲」与「习惯手动翻找」的双重需求，平台构建校园生活五大细分市场：

| 一级分类 | 推荐二级标签 | 核心结构化字段 |
| :--- | :--- | :--- |
| **课程资料 & 书籍** | 专业教材、出国留学（托福/GRE）、考研资料、通选笔记、课外读物 | 院系、课程名称、版次、有无笔记/划线 |
| **数码 3C & 影音** | 笔记本电脑、iPad/平板、手机配件、鼠标键盘、显示器、耳机音响 | 品牌、型号、保修状态、功能瑕疵程度 |
| **校园出行 & 运动** | 二手自行车、滑板、球拍器材、健身护具、户外露营 | 车型/尺寸、轮胎新旧程度、是否附锁 |
| **宿舍生活 & 家电** | 小型冰箱、电风扇、除湿机、收纳置物、台灯、桌椅 | 宿舍区限制（万柳/燕园等）、功率规格 |
| **美妆服饰 & 周边** | 应试正装、运动卫衣、校庆文创、化妆护肤、鞋包配饰 | 尺码、男女款、全新未拆/成色 |

* **智能分类映射**：卖家发布物品时，Vision-Language 模型根据商品图片与文字自动预测分类与标签，卖家仅需一键确认或手动微调。

---

### 3.3 买家端核心功能

#### 3.3.1 意图订阅与「系统代蹲」智能体 (Intent-Driven Agent)
* **流程**：
  1. 买家输入自然语言意图（例如：*「蹲一个万柳附近、300 元以内、适合自习室办公的静音鼠标」*）。
  2. 系统解析为硬性约束（`品类=数码/鼠标`, `价格<=300`, `校区=万柳`）与语义偏好（`静音/人体工学`）。
  3. 进入「漏斗式分级检索架构」后台监听。
  4. 新商品上架并满足阈值时，在秒级时间内向买家推送通知（附匹配理由、成色亮点与卖家报价）[cite: 2]。
* **规格限制**：每位买家最多可同时挂起 5 个活跃代蹲任务，默认生命周期为 14 天（支持一键续期或提前终止）。

#### 3.3.2 物品流式浏览与多维混合检索 (Hybrid Search)
* **流式加载**：瀑布流呈现商品卡片（封面图、成色标签、价格、所在校区、距发布时间）[cite: 2]。
* **混合检索**：结合关键词精准比对（BM25）与稠密向量语义检索，支持错别字纠错与学科缩写识别。
* **多维过滤**：支持价格区间、校区、成色等级、发布时间组合筛选。

#### 3.3.3 收藏、降价追踪与安全线下当面交易规划
* **收藏夹**：收藏的商品降价时，系统主动推送降价动态。
* **线下当面交易地点建议**：根据双方所属校区与时间，推荐理教大厅、万柳学区前台等校内安全交接点。
* **用户协同反馈失效信息**：买家线下沟通发现物品已售出时，可点击「反馈已售」，协助系统维护库存真实性。

---

### 3.4 卖家端核心功能

#### 3.4.1 多模态识图「一键生成商品发布草稿」(Auto-Drafting Agent)
* **流程**：卖家上传 1~3 张物品照片[cite: 2] $\to$ Vision-Language 模型识别品类、外观成色与磨损细节 $\to$ 调用历史成交数据推荐合理价格区间 $\to$ 自动填入结构化标题、描述、标签与推荐价格[cite: 2]。
* **指标**：多模态识别表单自动填充覆盖率 $\ge 80\%$，发布时间由传统 3 分钟大幅缩减至 30 秒以内。

#### 3.4.2 商品生命周期管理
* **状态机流转**：
  * `ACTIVE`（在售中 - 纳入检索推荐池）
  * `RESERVED`（已预订 - 暂时隐藏，不参与推荐）
  * `SOLD`（已售出 - 归档进入历史比价库）
  * `EXPIRED`（超时失效 - 触发动态 TTL 下架）
  * `BANNED`（违规封禁 - 经自动审核或人工判定强制下架）[cite: 2]

#### 3.4.3 离线智能代回复 (Offline Proxy Agent)
* **功能描述**：卖家可自选开启「离线代回复」，在课堂或科研期间代为回复标准常见问题[cite: 2]。
* **安全约束**：
  * 仅依据商品客观属性、交付偏好进行事实性回答。
  * 严格禁止代理降价，遇议价统一回复「已记录出价，待卖家上线亲自确认」。
  * 买家确认购买或约定线下当面交易时，即时推送唤醒卖家接管。

---

### 3.5 买方发布（求购看板）与反向撮合智能体

#### 3.5.1 搜索失败引导转求购看板
* **触发机制**：买家搜索无结果或相似度低于 60% 时，界面主动引导：*「找不到心仪物品？一键将搜索转为【求购发布】」*。
* **求购信息规格**：
  * **必填**：需求品类、期望名称、预期预算（上限/下限）、理想交接校区、有效期限（默认 7 天）。
  * **选填**：特定型号、成色容忍度（如「微瑕可接受」）。

#### 3.5.2 面向卖方的反向撮合智能体 (Seller-Facing Agent)
* **潜在供给感知**：智能体自动扫描「因过期下架但未售出」的历史库存，或曾发布过相关周边的卖家画像。
* **向潜在卖家定向推送求购信息**：当新求购单发布时，若计算出历史卖家库存高度吻合，发送征询私信：
  > *「同学你好！万柳有同学发布求购【Dell 显示器】（预算 350 元），与你上周下架的物品高度吻合，是否一键重新上架对接该买家？」*
* **快速对接通道**：卖家在求购页面点击「我有这件物品」，可直接套用买家规格发起定向报价。

### 3.6 个性化推荐系统

#### 3.6.1 推荐位置与策略
1. **首页推荐流（「燕园精选」）**：登录时展示，兼顾用户偏好与长尾商品曝光。
2. **商品详情页底部（「猜你喜欢」）**：推荐同类替代品或互补品。

#### 3.6.2 两阶段推荐架构
* **召回层 (Recall)**：
  * 基于内容的召回 (CBF)：用户历史浏览/收藏标签 vs 商品元数据。
  * 协同过滤召回 (CF)：行为路径相似同学的偏好召回。
  * 时空上下文召回：同校区/同宿舍园区商品赋予加权权重。
* **排序与重排层 (Ranking & Re-ranking)**：
  * 预测点击率 (CTR) 与互动概率；
  * 动态时间衰减（避免老旧帖子长期占据曝光）；
  * 多样性控制（连续 5 个商品内不得出现 3 个以上相同一级品类）。

---

### 3.7 管理端核心功能

#### 3.7.1 多模态自动合规审核 Agent (Compliance Engine)
* **审核范围**：
  1. 违禁品识别：管制器具、违法医药品、代考代写服务、易燃易爆物[cite: 2]。
  2. 校外欺诈引流：自动识别图片水印二维码、隐藏电话号码及诱导校外转账关键词[cite: 2]。
* **处置动作**：高风险违规（置信度 > 90%）立即拦截发布并限制账号权限；中风险进入人工复审队列[cite: 2]。

#### 3.7.2 争议仲裁与智能事实摘要
* **处理流程**：发生申诉时，Agent 自动调取聊天记录、商品承诺、上传凭证，提炼不超过 200 字的争议焦点摘要，辅助管理员快速定责[cite: 2]。

## 4. 底层技术架构与亮点设计

### 4.1 漏斗式分级检索架构 (Funnel Cascaded Retrieval)
解决传统 Agent 全量即时比对导致的 **Token 消耗过高与响应延迟** 痛点：

```text
[卖家发布新帖] ──► [一次轻量处理后入库]
                    提取元数据 + 生成文本稠密向量 Embedding
                              │
                              ▼
第一层：零 Token 粗筛层 (SQL Metadata Filter)
  • 价格超出预算？──► 立即剔除 (0 Token)
  • 校区完全不匹配？──► 立即剔除 (0 Token)
                              │
                              ▼
第二层：向量相似度快筛 (Dense Vector Search)
  • 计算买家需求向量与帖子向量的余弦相似度 (0 Token, <30ms)
  • 相似度 < 85%？──► 剔除，继续等待新商品
                              │
                              ▼ 仅 Top 1% 高价值匹配进入门控
第三层：按条件唤醒智能体精筛 (Agent Semantic Reasoning)
  • 唤醒智能体：比对隐含条件（静音、成色瑕疵程度）
  • 生成个性化推送卡片并私信买家
```

* **预期效果**： Token 消耗下降 95% 以上，平均检索延迟降低至 50ms 以内。

---

### 4.2 信息动态失效与主动确认机制 (Anti-Staleness)
针对线下二手交易缺乏支付闭环、易产生「僵尸帖子」的痛点，建立四层过滤机制：
1. **语义追加监听**：帖子下方的追加评论出现「已出」、「封楼」、「私了」等词，状态自动推进为 `SOLD`。
2. **品类动态 TTL**：
   * 短时效品类（票券、急出零食）：TTL = 24 小时。
   * 中时效品类（数码 3C、教材）：TTL = 7 天。
   * 长时效品类（冷门书籍、宿舍家具）：TTL = 30 天。
3. **高匹配意向主动确认机制**：当匹配度 > 90% 时，在推送前由 Agent 向卖家发送轻量确认：
   > *「同学你好！有同学看中了你的商品，请问目前仍在售吗？（回复 1 在售 / 2 已售）」*
4. **用户反馈闭环**：买家一键反馈「已失效」累计 2 次，系统自动暂停推荐并触发人工确认。

## 5. 非功能性需求 (NFR)

* **系统性能**：首页推荐流 P95 延迟 $< 300\text{ms}$；向量相似度检索 P95 延迟 $< 50\text{ms}$；并发支撑高峰期 $\ge 200\text{ QPS}$。
* **数据隐私与安全**：私信中敏感信息（手机号、微信号）默认提供脱敏防护；校园身份信息加密存储。
* **代码质量与测试规范**：关键业务逻辑与核心撮合算法需具备单元测试覆盖，保证系统稳定可维护。
