# 站内意见反馈

桌面侧栏和手机页面底部的“联系我们”旁增加“意见反馈”。原有联系邮箱保留。

## 使用流程

1. 点击“意见反馈”，登录后填写功能异常、使用建议或其他问题。
2. 内容为 5–3000 字，可上传最多 3 张 JPG、PNG、WebP 截图，每张不超过 6 MB。表单默认附带当前站内路径，用户可以取消；不附带 URL 查询参数。
3. 提交后进入详情，可在“我的反馈”查看历史和补充说明。
4. 管理员进入“审核工作台 → 用户反馈”，按状态筛选，回复并更新为待处理、处理中、已解决或暂不采纳。每次更新必须填写说明。
5. 回复进入提交人的站内通知中心，点击可直达详情。只把已加载的通知标为已读，读取期间的新回复仍保留未读。该功能不创建聊天消息或邮件发送任务。
6. 用户对已解决或暂不采纳的反馈继续补充后，状态重新变为待处理。

商品及聊天举报仍通过各自入口处理。

## 权限与存储

- 普通用户只能访问自己的反馈、回复和截图；管理员通过管理接口查看已提交反馈。
- 截图存储在应用数据目录的 `feedback-uploads/`，不使用公开 `/uploads/` 静态路径。未提交截图仅上传者可见，提交后管理员可访问。
- 反馈每用户每小时最多 5 条、补充回复最多 30 条、截图上传最多 20 张。列表每页 20 条，管理员支持状态筛选。
- 新增 `feedbacks`、`feedback_replies`、`feedback_attachments`、`feedback_notices` 四张表，由已有数据库准备流程自动创建。提交、回复及处理操作写入现有审计日志。
- 截图上传会校验真实图片格式、尺寸并重新编码；同一张截图只能关联一次反馈。

## 发布与回退

部署前备份数据库和完整应用数据目录；新版本启动时创建新表，无需修改已有业务表。文件备份与恢复必须包含 `feedback-uploads/`，只复制商品 `uploads/` 会遗漏反馈截图。

回退旧应用版本时保留新增表和截图目录，旧版本不展示反馈；重新升级后可继续使用。不要通过恢复旧数据库覆盖上线后新增的反馈或交易数据。

## 验证

新增测试覆盖用户与管理员完整往返、状态重开、通知已读边界、截图隔离、角色权限、输入校验、频率限制、分页及重复数据库准备。原有聊天图片测试验证共享图片处理函数的兼容性。

```powershell
.\.venv\Scripts\python.exe -m pytest backend/tests -q
cd frontend
npm ci
npm run build
```

人工验收：从“意见反馈”登录并返回表单，提交测试反馈，切换管理员回复，再切回提交人，通过通知查看回复并确认未读数量减少。
