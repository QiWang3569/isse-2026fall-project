# 北大邮箱登录与站内聊天

## 邮箱注册与登录

登录弹窗分为“注册账号”“验证码登录”“密码登录”。注册时填写北大邮箱、昵称、校区及密码，然后收取 8 位一次性验证码；验证成功才创建普通用户。已有账号选择验证码登录，只需邮箱和验证码。仅接受邮箱域名恰好为 `pku.edu.cn` 或 `stu.pku.edu.cn` 的地址。验证邮件所有权是注册条件；单纯输入校内邮箱地址不能完成注册。

已有账号也可使用“邮箱＋密码”登录。此前只用验证码注册且尚未设置密码的账号，可在“当前账号”或密码登录页的“首次设置或忘记密码”入口验证邮箱后设置密码；这些入口也可重置密码。密码登录不要求邮件服务当时可用，但注册、首次设置和忘记密码重置都需要能正常收取验证码。仅已验证过邮箱的账号可以设置密码，原有验证码登录仍可使用。

新密码长度为 9–128 位，需同时包含英文字母和数字；不要求大小写混合或特殊符号，前后空格会作为密码的一部分保留。服务器只保存随机加盐后的 `scrypt` 摘要，不保存明文；所用参数为 N=2^15、r=8、p=3，符合 [OWASP 密码存储建议](https://cheatsheetseries.owasp.org/cheatsheets/Password_Storage_Cheat_Sheet.html)列出的 scrypt 配置。密码错误按账号限制为 15 分钟内最多 8 次，并对来源地址另设 60 次限制；未知邮箱和错误密码使用相同提示。重置密码后，该账号的旧登录会话失效，当前设备获得新会话。

在项目根目录 `.env` 中配置：

```dotenv
DEMO_MODE=false
AUTH_CODE_SECRET=自行生成的至少32字符随机值
SMTP_HOST=邮件服务主机
SMTP_PORT=465
SMTP_USER=邮件服务账号
SMTP_PASSWORD=邮件服务凭据
SMTP_FROM=已授权的发件地址
```

端口 465 或 994 使用 SMTP SSL；其他端口先执行 STARTTLS。按[北大邮件服务官方说明](https://its.pku.edu.cn/service_1_mail.jsp)，`@pku.edu.cn` 发信使用 `smtp.pku.edu.cn:465`，`@stu.pku.edu.cn` 发信使用 `smtphz.qiye.163.com:994`；学生邮箱的 SMTP 密码应按[校方客户端说明](https://its.pku.edu.cn/about_8.jsp)使用客户端授权码。本机对学生邮箱服务器实测发现，`SMTP_USER` 需填完整的 `@stu.pku.edu.cn` 发件地址；仅填学号被服务器以 535 拒绝。没有配置随机密钥、SMTP 主机和发件地址时，邮箱登录返回 503，页面明确显示不可用，不会绕过验证创建用户。本机已由用户确认真实收件并完成注册登录；其他部署环境仍需自行配置 SMTP，退信和批量发信尚未验证。不要把 SMTP 凭据提交到仓库或写入前端。

### 换成项目公共发件邮箱

可以使用专门为项目开设、由项目管理人员共同管理的邮箱，负责验证码和已启用的未读站内信提醒；用户注册时仍只接受 `@pku.edu.cn` 和 `@stu.pku.edu.cn`。发件邮箱可由支持 SMTP 的邮件服务提供，不需要本身是北大邮箱。若希望使用北大域名的多人共享工作邮箱，先向学校邮件服务管理方确认申请和使用资格，不能自行把个人邮箱改成公共邮箱。

取得项目邮箱及它的 SMTP 发信权限后，只需在项目根目录的本地 `.env` 改这五项，并重启后端：

```dotenv
SMTP_HOST=该邮箱服务商给出的SMTP主机
SMTP_PORT=该服务商给出的加密SMTP端口
SMTP_USER=项目邮箱的完整登录账号
SMTP_PASSWORD=项目邮箱的SMTP授权码或应用密码
SMTP_FROM=项目邮箱的完整发件地址
```

`SMTP_USER` 和 `SMTP_FROM` 通常填写同一个完整邮箱地址，必须以服务商允许的发件身份为准。`AUTH_CODE_SECRET` 保持原来的随机密钥；切换发件人不需要修改用户数据库或登录白名单。先在本地向自己的北大邮箱发送一次验证码，确认邮件真正到达且能完成登录。凭据只保存在服务器 `.env`，不要发给用户或提交到 GitHub。

使用普通 `@163.com` 邮箱发信时，先在网易邮箱网页的「设置 → POP3/SMTP/IMAP」开启 SMTP 并获取客户端授权码。`SMTP_HOST` 填 `smtp.163.com`，`SMTP_PORT` 填 `465`，`SMTP_USER` 和 `SMTP_FROM` 填项目邮箱的完整地址，`SMTP_PASSWORD` 填客户端授权码，不能填网页登录密码。此配置与北大学生邮箱使用的 `smtphz.qiye.163.com:994` 不同。[163 邮箱 SMTP 配置参考](https://publications.lexmark.com/publications/lexmark_hardware/CX53x_CX63x/UG/html/en/configuring-smtp-server-for-e-mail-topic.html)

验证码 10 分钟有效，验证后即失效；同一邮箱 60 秒内不能重复申请，一小时内最多发送 5 次；错误验证最多 5 次。数据库只保存带密钥的摘要及有效期，不保存明文验证码。邮件域名并不能证明用户当前仍具有北大学籍或教职身份；若上线政策要求更严格的在校身份，应再接入校园统一认证。

演示模式保留原来的三种演示身份，方便本地展示。设为 `DEMO_MODE=false` 后演示登录与种子关闭；普通邮箱用户不能通过注册得到管理员身份。

正式环境中，管理员先用自己的北大邮箱完成一次验证码注册，然后由掌握**服务器本机访问权限**的人在项目根目录执行：

```bash
PYTHONPATH=backend .venv/bin/python -m app.admin_cli grant admin@pku.edu.cn
```

把示例地址替换成该管理员实际注册的邮箱。权限调整后，该用户退出并重新登录即可进入审核工作台；撤销权限时把 `grant` 改为 `revoke`。该命令直接使用服务器 `.env` 里的数据库连接，只应由部署管理员在服务器本机运行。网页注册本身不会授予管理员权限。

## 商品站内聊天

登录买家可在在售商品详情点击“联系卖家”，输入消息后确认发送。一个买家与一件商品对应一条会话；仅该买家与商品卖家可读取及发送。卖家在“站内消息”查看未读提示和回复。咨询草稿只填入输入框，仍需用户确认发送。

新会话仅能由买家针对在售商品发起。商品随后预订、售出或撤回，既有会话仍可继续沟通。消息支持文字和图片，单条最多 2000 字、3 张图片，每张不超过 6 MB，页面每 8 秒读取新消息。已注册用户可在个人主页开启未读站内信邮件提醒，默认延迟 5 分钟，并将同一会话合并发送；服务器配置、队列重试和投递限制见 [邮件提醒说明](FOLLOWUP_FEATURES.md#未读站内信邮件提醒)。图片需登录站内查看；系统推送和 WebSocket 尚未实现。

双方可随时拉黑对方；拉黑后双方都不能再发送消息或开启新会话，旧消息仍可查看，拉黑者可解除。用户可以举报对方的具体消息，每人对同一条消息只能举报一次。管理员仅在审核工作台看到**被举报的那条消息**和举报原因，可选择隐藏消息或驳回，并需填写依据、确认操作；操作留审计记录。隐藏的消息在普通会话中仅显示“此消息已被管理员隐藏”。举报不会自动隐藏消息，也不会自动封禁账号。

聊天正文默认保存 180 天，可由服务器端 `CHAT_RETENTION_DAYS` 调整，范围 30–3650 天。启动后及每 24 小时清理到期消息；有尚未结案或仍在保留期的举报时，该消息继续保存为证据。已结案举报及其证据至少保存 365 天（若聊天保留期更长，则按较长期间保存），到期后一起清理。数据库备份的保留周期需由实际部署方单独配置。管理员应只为处理举报访问内容，不应把聊天内容复制到公开日志。

## 交易状态与已售信息

买家可以在会话里申请预订；卖家确认后商品进入“已预订”，退出搜索和推荐。卖家可以拒绝，买家可以取消；取消已确认的预订后，未过期商品重新在售。卖家确认售出后，买家可以确认收到商品。卖家在商品详情仍可手动标记“已预订”“已售出”或重新上架；手动改动会同步对应会话的交易状态。

买家发现商品已售但页面仍在售时，可点“反馈已售”。反馈不会自动下架，卖家在自己的商品详情核实后选择“确认已售”或“仍在售”。买家买到商品后，可在匹配通知点“已买到这件”，或在代蹲任务点“已买到”；代蹲任务随之结束。旧匹配通知保留记录，但会显示商品实时状态，已预订、售出、过期或被审核隐藏的商品标记为不可咨询。

旧数据库启动时增量增加新字段，并创建验证码、密码尝试、会话、举报、拉黑和已售反馈表。已有演示数据及会话不会被删除；聊天记录会按上述保留规则清理。旧账号的密码初始为空，必须先通过邮件验证码设置，不能用未设置过的密码登录。
