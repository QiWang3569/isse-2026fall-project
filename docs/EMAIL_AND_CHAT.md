# 北大邮箱登录与站内聊天

## 邮箱注册与登录

用户在同一入口填写邮箱，收取 8 位一次性验证码。首次验证创建普通用户，需填写昵称与校区；已有账号验证后直接登录。仅接受邮箱域名恰好为 `pku.edu.cn` 或 `stu.pku.edu.cn` 的地址。验证邮件所有权是注册条件；单纯输入校内邮箱地址不能完成注册。

在项目根目录 `.env` 中配置：

```dotenv
DEMO_MODE=false
AUTH_CODE_SECRET=自行生成的至少32字符随机值
SMTP_HOST=邮件服务主机
SMTP_PORT=465
SMTP_USER=邮件服务账号
SMTP_PASSWORD=邮件服务凭据
SMTP_FROM=已授权的发件地址
```

端口 465 或 994 使用 SMTP SSL；其他端口先执行 STARTTLS。按[北大邮件服务官方说明](https://its.pku.edu.cn/service_1_mail.jsp)，`@pku.edu.cn` 发信使用 `smtp.pku.edu.cn:465`，`@stu.pku.edu.cn` 发信使用 `smtphz.qiye.163.com:994`；学生邮箱的 SMTP 密码应按[校方客户端说明](https://its.pku.edu.cn/about_8.jsp)使用客户端授权码。本机对学生邮箱服务器实测发现，`SMTP_USER` 需填完整的 `@stu.pku.edu.cn` 发件地址；仅填学号被服务器以 535 拒绝。没有配置随机密钥、SMTP 主机和发件地址时，邮箱登录返回 503，页面明确显示不可用，不会绕过验证创建用户。本机已由用户确认真实收件并完成注册登录；其他部署环境仍需自行配置 SMTP，退信和批量发信尚未验证。不要把 SMTP 凭据提交到仓库或写入前端。

验证码 10 分钟有效，验证后即失效；同一邮箱 60 秒内不能重复申请，一小时内最多发送 5 次；错误验证最多 5 次。数据库只保存带密钥的摘要及有效期，不保存明文验证码。邮件域名并不能证明用户当前仍具有北大学籍或教职身份；若上线政策要求更严格的在校身份，应再接入校园统一认证。

演示模式保留原来的三种演示身份，方便本地展示。设为 `DEMO_MODE=false` 后演示登录与种子关闭；普通邮箱用户不能通过注册得到管理员身份。

## 商品站内聊天

登录买家可在在售商品详情点击“联系卖家”，输入消息后确认发送。一个买家与一件商品对应一条会话；仅该买家与商品卖家可读取及发送。卖家在“站内消息”查看未读提示和回复。咨询草稿只填入输入框，仍需用户确认发送。

新会话仅能由买家针对在售商品发起。商品随后预订、售出或过期，既有会话仍可继续沟通。消息仅支持文字，单条最多 2000 字，页面每 8 秒读取新消息；目前没有邮件、系统推送、图片附件或 WebSocket。聊天记录持久化在数据库中，未来需要补充举报、封禁、保留期限与敏感信息保护策略后再向较大范围开放。

旧数据库启动时增量增加用户邮箱列，并创建验证码、会话与消息表。已有演示数据及会话不会被删除。
