# 通知与商品图片更新

日期：2026-10-23。代码与本地验证完成，尚未部署生产。

## 用户行为

- 铃铛计数由后端汇总公告、聊天、代蹲匹配、站内反馈回复和买家反馈已售的未读数，不受列表 50/100 条限制。
- 公告列表显示摘要；打开全文后才提交该条已读状态。正文保持打开，关闭后不再出现在铃铛未读列表，历史公告仍可分页查看。游客可以阅读历史公告，不产生阅读记录。
- 买家反馈已售的“未读”和“待处理”分开：点击去处理并成功打开商品后消除该条未读，待处理事项保留至卖家确认或驳回。
- 读状态在同源标签页之间同步；刷新时保留上一份计数，忽略操作前发出的旧响应，避免红点闪动或回升。网络失败保留状态并提供重试。
- 聊天通知直接打开对应会话；后台页面不自动标记聊天已读。读取消息时只提交实际取回的消息 ID，不会顺带清除稍后到达的新消息。
- 商品主图和补充图可打开图片查看器，支持九图切换、键盘方向键、缩略图、1–4 倍缩放、拖动、手机滑动及双指缩放。Esc 先关闭图片查看器，商品详情和滚动位置保留。无图商品不显示放大入口，图片失败可重试。

## 接口与数据兼容

- 新增 `GET /api/v1/notification-summary`，返回分组未读数、总未读数和待处理已售反馈数。
- 新增 `GET /api/v1/announcements/feed?page=1&size=20&unread_only=false`，返回 `items/total/page/size`，条目包含当前用户的 `is_read`；旧公告接口继续保留。
- 新增 `POST /api/v1/sale-feedback/{id}/read`，仅商品所有者可调用。`sale_feedback` 新增可空 `read_at`；升级保留旧记录和处理状态，重复启动不清除阅读状态。
- 聊天已读接口现在要求 `{"ids": ["实际取回的消息 ID"]}`，每次 1–50 条。前后端必须一同发布，旧前端无请求体的调用会收到 422。
- 代蹲通知列表新增 `unread_only` 过滤；具体代蹲任务仍可查看历史匹配。会话和已售反馈列表优先返回未读记录。
- 同标签页通知变更事件及 localStorage 广播仅携带刷新信号，不包含消息、账号或凭证；跨标签页各自按服务端身份重新查询。
