# B. 体验与人性化操作

以下用例不以“功能对不对”为目标，而以“是否顺畅、是否容易理解、是否少走弯路”为判断标准。

- [ ] 新用户未登录时，能一眼看出“我可以逛，但要登录才能收藏/发布/代蹲”，且登录入口足够显眼
- [ ] 从“逛逛校园”到“发布闲置”“帮我代蹲”“发布求购”三个动作，是否都能在 2 步内到达
- [ ] 代蹲创建流程：输入需求 → 解析 → 确认条件 → 保存，步骤清晰，条件确认区能看懂每一项含义
- [ ] 收到匹配通知后，能否直接从通知进入商品详情，并看到“为什么推荐它”的理由
- [ ] 咨询草稿从“生成”到“发送”是否顺畅，不需要用户复制粘贴或重复输入
- [ ] 站内消息的未读提醒是否明显，点击提醒后是否直接进入对应会话
- [ ] 交易操作（预订/售出/取消）前后，买卖双方看到的商品状态和下一步提示是否一致、易懂
- [ ] 举报入口是否清晰，举报理由填写是否有占位示例，提交后是否有明确反馈
- [ ] 空状态（无搜索结果、无消息、无收藏、无通知）是否有友好文案和下一步引导
- [ ] 表单校验失败时，错误提示是否定位到具体字段、是否通俗易懂
- [ ] 加载中 / 保存中 / 失败重试是否有明确状态反馈，避免用户重复点击
- [ ] 移动端窄屏下，高频功能（搜索、消息、发布、代蹲）是否无需反复切换即可使用
- [ ] 价格、时间、有效期、成色等关键信息是否有统一、易读的展示格式
- [ ] 演示账号与正式邮箱登录在登录弹层中是否区分清楚，避免误用

# C. 待改进问题清单（需修复）

每一项都标注“现状 / 证据 / 建议”，修复完成后勾选“已修复”。

## C1. 站内消息入口太深（功能不聚合、不顺手）

- 现状：顶部导航只有“逛逛校园 / 求购看板 / 我的主页”三项，站内消息被放在“我的主页 → 站内消息”二级入口；头像有未读角标，但点击进入的是个人主页而非消息列表。
- 证据：`frontend/src/App.tsx` 的 `nav` 数组只有 `market / wanted / profile`；消息在 `frontend/src/Profile.tsx` 的 `sections` 里。
- 建议：顶部导航直接增加“消息”，或让头像未读角标点击后直接跳转消息列表。
- [ ] 已修复并回归验证

## C2. 通知与站内消息分离，入口分散（功能不聚合）

- 现状：代蹲匹配通知在顶部铃铛弹层，站内聊天在“我的主页 → 站内消息”，两套“消息”体系分开，用户容易混淆“通知”和“聊天”。
- 建议：统一消息中心，或在铃铛通知里提供“去站内消息”快捷入口。
- [ ] 已修复并回归验证

## C3. 咨询草稿流程不顺畅（不顺手）

- 现状：咨询草稿已改为只在站内消息生成——从商品详情点“联系卖家”进入站内消息（新会话）后，输入框上方有“咨询草稿”按钮，点击生成并预填到输入框；商品详情的“咨询草稿”按钮和草稿弹层已移除。
- 证据：`frontend/src/AccountAndChat.tsx` 的 `generateDraft` 与输入框上方按钮；`frontend/src/App.tsx` 已删除草稿区。
- 建议：待浏览器回归确认交互是否顺畅。
- [√] 已修复，待回归验证

## C4. 管理员审核入口隐蔽（功能不聚合、不合理）

- 证据：`frontend/src/App.tsx` 中 `Flag` 图标“反馈已售”与“举报问题”相邻。
